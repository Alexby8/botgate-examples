# Черновик заявки на консультацию

Нужны HTTPS, тестовый бот и 64-битный PHP 8.3+ с mbstring и PDO SQLite. Начните в этой папке.

1. Создайте закрытый каталог вне веб-корня. Задайте APP_DB с абсолютным путём к базе для CLI и веб-процесса. PHP должен иметь право записи в этот каталог. Задайте BOT_TOKEN для веб-процесса из доверенного окружения.
2. Выполните `php init.php`. Настройте HTTPS-сайт с корнем `public/` и обработкой PHP. Добавьте его URL `/form.html` в меню тестового бота. [Настройка кнопки меню](https://bot-gate.ru/guides/telegram-mini-app-html-php-form#launch)
3. Откройте форму из личного чата, выберите «Перенос данных» и введите вопрос. Дождитесь «Черновик сохранён», закройте и откройте форму. Поля восстановятся.
4. Откройте форму одновременно в двух клиентах для того же аккаунта. Дождитесь сохранения в первом и введите другой текст во втором. Второй получит конфликт. После копирования своего текста можно загрузить серверную версию.
5. Отправьте вопрос длиной не менее десяти символов. Форма покажет номер заявки. Запрос к `drafts` покажет `state=submitted`, пустые поля и `application_id`. Повтор исходного POST вернёт тот же номер. Кнопка «Новая заявка» открывает другой draftId.

| Файл | Назначение |
| --- | --- |
| `public/form.html`, `public/api.php` | Форма, восстановление, последовательное автосохранение и POST. |
| `auth.php` | Подпись Telegram, срок initData и ID владельца. |
| `drafts.php`, `schema.sql` | Версии, конфликты, повтор операции и атомарная запись заявки. |
| `cloud-draft.mjs` | Отдельная альтернатива для короткой формы через CloudStorage. |

В учебном варианте журнал operations хранит полный ответ для повторов. Для хранения пользовательского текста задайте срок очистки черновиков и ответов журнала. PHP вне Laravel читает переменные процесса, создание файла .env само по себе их не добавляет.
