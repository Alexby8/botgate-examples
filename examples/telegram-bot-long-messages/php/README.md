# Последовательная отправка длинного отчёта

Нужны 64-битный PHP 8.3+ с mbstring, PDO SQLite и cURL. Команды выполняйте из этой папки. Первый шаг только подготавливает данные.

```bash
php prepare-parts.php > parts.json
```

В `report.txt` три группы учебных записей. В `parts.json` ожидаются три пронумерованные части с HTML-экранированием. Задайте `PARTS_DB` с путём к SQLite вне веб-корня, `BOT_TOKEN` тестового бота и `TELEGRAM_CHAT_ID` своего тестового чата. Откройте этот чат кнопкой «Старт», затем выполните:

```bash
php run-parts.php daily-2026-11-18
```

Команда отправляет части в чат по одной. Повтор с тем же ID читает первоначальный набор и адресат из SQLite. Для новой версии отчёта используйте новый ID. При 429 подождите `next_at` и повторите команду с тем же ID. Если первая неподтверждённая часть в состоянии `sending` или `unknown`, сначала сверьте чат. Для принятого сообщения отметьте часть `sent` и запишите `message_id`. Если после сверки решили повторить, остановите прежний отправитель и переведите только эту строку в `pending` с `next_at=0`.

| Файл | Назначение |
| --- | --- |
| `split-text.php`, `prepare-parts.php` | Разбивка исходника, заголовки и HTML. |
| `parts.sql`, `store-parts.php` | Атомарная запись исходного набора. |
| `send-next.php`, `run-parts.php` | Последовательная отправка, пауза и возобновление. |
| `transport.php`, `common.php`, `values.php` | Вызов Bot API и чтение настроек. |

Для сверки используйте `SELECT part_no,state,attempts,message_id,next_at FROM message_parts ORDER BY batch_id,part_no;`.
